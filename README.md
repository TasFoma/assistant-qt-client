# 🧠 «Мой спутник» — личный ИИ-ассистент

Полностью локальный ассистент: чат с нейросетью, задачи, календарь,
напоминания (по времени и месту), привычки, навигация, погода, поиск
в интернете, музыка и голос. Все данные — твои, ни один байт не уходит
в чужие облака.

## 1. Как всё устроено (архитектура)

```
                ┌─────────────────────────────────────────────┐
                │   СЕРВЕРНАЯ МАШИНА (tasfoma-l, всегда вкл.)  │
                │                                             │
                │  llama-server        ← нейросеть (порт 8080)│
                │  companion_server    ← «мозг»    (порт 8765)│
                │    ├── companion.db  ← вся база (рядом cexe)│
                │    └── server.log    ← лог                  │
                │  SearXNG (Docker)    ← поиск     (порт 8081)│
                └──────────────▲──────────────────────────────┘
                               │ TCP 8765, JSON-строки
                               │ (дома — по LAN, извне — Tailscale VPN)
              ┌────────────────┴───────────────┐
   ┌──────────┴─────────┐          ┌───────────┴──────────┐
   │  НОУТБУК           │          │  ТЕЛЕФОН (Android)   │
   │  qt_client.exe     │          │  «Мой спутник»       │
   │  интерфейс + голос │          │  Flutter-приложение  │
   └────────────────────┘          └──────────────────────┘
```

**Сервер (`companion_server`)** — безоконная программа, в ней живёт всё:
- SQLite-база `companion.db` (лежит рядом с exe!): чаты, задачи, события,
  напоминания, привычки, маршруты, профиль пользователя, настройки;
- парсер русских команд («напомни…», «добавь задачу…», «запомни…»,
  «как добраться…», «пить воду каждые 45 минут»);
- планировщик: следит за напоминаниями, шлёт утреннее приветствие
  с погодой и вечерний чек-ин;
- навигация (Nominatim + OSRM) и погода (open-meteo);
- прокси к нейросети: добавляет к каждому запросу контекст
  (дата, профиль «запомни…», планы дня, цели) и результаты поиска.

**Клиенты** — тонкие: показывают данные и шлют команды. Ничего не хранят,
кроме кэша. Клиентов может быть сколько угодно.

**Протокол**: TCP, порт 8765, JSON-объекты по одному в строке.
Первое сообщение — `{"type":"auth","token":"…"}`. Все типы сообщений
видны в `src/syncserver.cpp` (функция `handleLine`).

**Безопасность**: токен в базе (ключ `sync_token`) + Tailscale (WireGuard)
для доступа извне. Порт наружу не открывается.

## 2. Из чего состоит код

```
qt_client_clean/            ← этот репозиторий (C++/Qt)
  src/
    main_server.cpp         ← вход СЕРВЕРА (companion_server)
    syncserver.*            ← протокол, прокси к llama, поиск, маршруты с телефона
    plannermanager.*        ← задачи/события/напоминания/привычки/проактивность
    chatmanager.*           ← история чатов в SQLite
    commandparser.*         ← разбор русских команд и дат
    navigationmanager.*     ← геокодинг, маршруты, погода, статистика
    mentormanager.*         ← анализ настроения
    databasemanager.*       ← SQLite (схема + настройки)
    ─────────────────────
    main.cpp                ← вход КЛИЕНТА (qt_client)
    remotebackend.*         ← TCP-клиент сервера: кэш + операции для QML
    musicplayer.*           ← музыка из папки (Qt Multimedia)
    voiceinput.*            ← микрофон (Vosk) и озвучка (SAPI)
    qml/                    ← интерфейс: Main, ChatPanel, SidePanel, панели, диалоги
  CMakeLists.txt            ← две цели: qt_client и companion_server

../android_client/          ← телефон (Flutter/Dart)
  lib/
    sync_service.dart       ← TCP-клиент сервера
    llama_service.dart      ← чат (через сервер, фолбэк напрямую)
    notification_service.dart ← локальные уведомления (работают офлайн)
    screens/                ← Чат / Планы / Напоминания / Настройки
```

## 3. Как вносить изменения

**Десктоп/сервер** (нужны: Qt 6.10 msvc2022_64, VS 2022, CMake):
```bat
cd qt_client_clean
cmake -S . -B build -DCMAKE_PREFIX_PATH="C:/Qt/6.10.2/msvc2022_64"
cmake --build build --config Debug -j 8            # обе программы
```
- Клиент: `build\Debug\qt_client.exe` (после изменений просто перезапусти).
- Сервер: собери Release `cmake --build build --config Release --target
  companion_server`, замени exe в папке сервера на той машине, перезапусти.
- Новые Qt-модули → добавь в `find_package` и `target_link_libraries`,
  затем один раз `windeployqt6.exe` на exe.
- Тест парсера команд: `qt_client... build\Debug\companion_server.exe`
  не нужен — правь `commandparser.cpp`, собери и проверь сервером.

**Телефон** (нужен Flutter SDK):
```bat
cd android_client
flutter run                      # быстрый цикл с горячей перезагрузкой
flutter build apk --release      # готовый APK
flutter install                  # поставить на подключённый телефон
```

**Новая команда ассистенту** («сделай X по фразе Y») — три места:
1. `commandparser.cpp` → распознать фразу, вернуть тип+поля;
2. `syncserver.cpp` → `runCommand()` — выполнить и ответить;
3. готово: обе платформы получают её автоматически (команды идут через сервер).

## 4. Перенос сервера на другую машину

База лежит рядом с exe, поэтому:
1. Останови сервер (закрой процесс `companion_server.exe`).
2. Скопируй **всю папку сервера** (в ней exe, DLL и `companion.db`)
   на новую машину.
3. Запусти там `install.bat` от имени администратора
   (брандмауэр + автозагрузка + запуск).
4. Поставь на новую машину Tailscale (тот же аккаунт) и запусти
   llama-server (поправь путь в `start_all.bat`, если отличается).
5. На клиентах поменяй IP: ноут — ⚙ в шапке чата; телефон — Настройки.
   Токен не меняется (он в базе).

## 5. Установка клиентов на другие машины

**Windows**: папка `companion_client` (готовая лежит в Downloads) —
скопируй на машину, запусти `install.bat`. Он сделает ярлык на рабочем
столе и автозагрузку. В ⚙ проверь IP сервера и токен. Для доступа
не из дома — установи Tailscale под тем же аккаунтом.
Голосовой ввод опционален: нужен Python + `pip install vosk sounddevice`
и модель `vosk-model-ru-0.22`.

**Android**: `android_client\build\app\outputs\flutter-apk\app-release.apk` —
скинь на телефон и установи. В Настройках: IP сервера + токен.

## 6. Если что-то сломалось

| Симптом | Причина и лечение |
|---|---|
| «Нет связи с сервером» на клиентах | На серверной машине не запущен `companion_server`. Ярлык «Мой спутник (сервер)» на её рабочем столе, либо перезагрузи машину (автозагрузка поднимет всё). |
| «Connection refused» в чате | Не запущен `llama-server`. Тот же ярлык `start_all.bat` поднимает и его. |
| Клиенты не подключаются, хотя сервер работает | Брандмауэр: перезапусти `install.bat` от админа (он открывает порт 8765 и переводит сеть в «Частную»). Извне — проверь, что Tailscale включён на обоих устройствах. |
| «Сервер отклонил токен» | Токен в ⚙ (ноут) / Настройках (телефон) не совпадает с серверным. Узнать серверный: на той машине `companion_server.exe --show-token`. |
| Ответы модели — бессвязный текст | В llama-server выбрана НЕ Instruct-модель. В приложении должны использоваться `Qwen2.5-7B-Instruct-Q4_K_M` / `qwen2.5-14b-instruct-q4_k_m`. |
| Поиск в интернете не работает | На серверной машине не запущен SearXNG (Docker). `docker start searxng`. |
| Напоминания на телефоне без звука/не приходят | Разреши приложению уведомления и «Будильники и напоминания» в настройках Android; отключи оптимизацию батареи для приложения. |
| Что-то странное | Логи: сервер — `server.log` рядом с exe; клиент — `app.log` рядом с exe. Присылай их содержимое ассистенту 😊 |

## 7. Дорожная карта (что можно добавить)

- **Навигация**: общественный транспорт (нужен OpenTripPlanner или 2GIS API),
  избранные места («домой», «на работу»), голосовое ведение по маршруту
  на телефоне, история и статистика поездок по неделям.
- Телефон: виджет на рабочий стол (задачи дня), офлайн-команды.
- Сервер: бэкап базы по расписанию (копия companion.db в облако/на ноут).
- Музыка на телефоне; общий плейлист с сервером.
- Дневник настроения с графиком; недельные отчёты о привычках.
- Файлы: «найди файл на сервере», передача файлов между устройствами.
